저장 대상 힌트: $ARGUMENTS

지금까지 이 대화에서 오간 내용을 검토해, 다음 세션에서도 유효하고 다시 알아야 할 만큼
중요한 것을 이 프로젝트의 메모리 시스템에 저장하라. `$ARGUMENTS`가 있으면 그 주제와
관련된 내용을 우선 검토하고, 없으면 대화 전체를 스캔하라.

## 절대 규칙 — 저장 경로

> CLAUDE.md의 "메모리" 섹션이 Claude Code 시스템 프롬프트의 auto memory 기본 경로
> (`~/.claude/projects/.../memory/`)를 **명시적으로 무시**하도록 지시하고 있다. 이 스킬로
> 저장하는 모든 메모리는 반드시 이 저장소 안의 `.claude/memory/` 디렉토리에 쓴다.
> `~/.claude/projects/...` 경로에는 절대 쓰지 않는다.

(참고: `.claude/agent-memory/<에이전트명>/`은 code-reviewer 등 **서브 에이전트 전용**
메모리 공간이다. 이 스킬은 메인 대화 메모리인 `.claude/memory/`만 다루며,
`agent-memory/`는 건드리지 않는다 — 각 서브 에이전트가 자신이 실행될 때 스스로 기록한다.)

## 1단계: 대화 스캔 — 저장할 가치가 있는지 판단

다음 4가지 유형 중 하나에 해당하는 내용이 있었는지 확인한다. 없으면 억지로 만들지 말고
"이번 대화에는 저장할 만큼 새로운 내용이 없습니다"라고 보고하고 종료한다.

- **user** — 사용자의 역할·목표·지식 수준·선호에 대해 새로 알게 된 것
- **feedback** — 사용자가 명시적으로 고친 방식("아니 그게 아니라"), 또는 이례적인 접근을
  이견 없이 승인한 것("응 그렇게 해줘"). 승인 확인도 놓치지 말 것 — 교정만 기록하면
  이미 검증된 접근 방식에서 서서히 멀어진다
- **project** — 누가 무엇을 왜, 언제까지 하기로 했는지, 진행 중인 이니셔티브·버그·의사결정
  (코드/git 로그로 유추 가능한 내용은 제외)
- **reference** — 외부 시스템(Linear/Slack/Grafana 등)에서 관련 정보를 찾을 수 있는 위치

## 2단계: 저장하면 안 되는 것 걸러내기

아래는 코드나 git 히스토리로 언제든 다시 확인 가능하므로 저장하지 않는다.

- 코드 패턴·아키텍처·파일 경로·프로젝트 구조 (코드 읽으면 됨)
- git 히스토리·최근 변경 내용·누가 뭘 고쳤는지 (`git log`/`git blame`로 충분)
- 디버깅 해결 방법·수정 레시피 (수정 자체가 코드에 남고, 이유는 커밋 메시지에 남음)
- CLAUDE.md·`.claude/rules/`에 이미 문서화된 내용
- 이번 대화에서만 의미 있는 일회성 작업 상태(진행 중인 구현 세부사항 등 — 이런 건 Plan/Task로
  관리할 내용이지 메모리가 아니다)

사용자가 명시적으로 저장을 요청한 내용이라도 위 제외 대상이면, 무엇이 "의외였는지"·
"왜 놀라웠는지"만 뽑아서 저장한다(원본 그대로 저장하지 않는다).

## 3단계: 기존 메모리와 중복 확인

`.claude/memory/MEMORY.md`를 먼저 읽고, 관련된 기존 메모리 파일이 있는지 확인한다.
- 있으면 그 파일을 갱신(오래된 내용 수정/제거 포함)한다 — 새 파일을 또 만들지 않는다.
- 없으면 3단계 형식에 맞춰 새로 만든다.
- project 유형처럼 빠르게 바뀌는 내용은, 이번 대화 내용이 기존 메모리와 충돌하면 최신
  대화 내용을 신뢰하고 기존 메모리를 덮어쓴다.

## 4단계: 저장 — 파일 작성 + 인덱스 등록 (2단계 필수)

**(a) 메모리 파일 작성** — `.claude/memory/{유형}_{짧은-kebab-case-주제}.md`:

```markdown
---
name: {짧은-kebab-case-slug}
description: {한 줄 요약 — 다음 세션에서 관련성을 판단하는 데 쓰이므로 구체적으로}
metadata:
  type: {user, feedback, project, reference}
---

{메모리 본문. feedback/project 유형은 다음 구조를 따른다:
1. 규칙/사실 자체
2. **Why:** 줄 — 사용자가 그렇게 말한 이유(과거 사건, 강한 선호 등)
3. **How to apply:** 줄 — 언제/어디서 이 지침이 적용되는지
관련 메모리는 [[다른-메모리-name]] 형식으로 링크한다. 상대적 날짜("어제", "다음 주
목요일")는 오늘 날짜 기준 절대 날짜로 변환해서 적는다.}
```

**(b) 인덱스에 포인터 추가** — `.claude/memory/MEMORY.md`에 한 줄만 추가:

```
- [제목](파일명.md) — 150자 이내 한 줄 요약
```

`MEMORY.md` 자체에는 절대 메모리 본문을 직접 쓰지 않는다 — 인덱스는 인덱스일 뿐이다.

## 5단계: 결과 보고

무엇을 새로 저장했는지, 무엇을 갱신했는지, 왜 저장할 가치가 있다고 판단했는지 3~5줄로
간결하게 보고한다. 저장한 파일 경로도 함께 알려준다.
